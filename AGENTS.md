# Правила ветвления микросервисов

## Структура веток

Каждый микросервис развивается в собственной ветке с базовой веткой вида:

```text
service-<microservice>/main
```

Рабочие изменения создаются в дочерней ветке:

```text
service-<microservice>/<feature-or-fix>
```

Например:

```text
service-files/main
service-files/upload-streaming

service-tasks/main
service-tasks/filter-swagger
```

## Ограничение области изменений

- Ветка сервиса должна содержать только изменения этого микросервиса.
- Изменения другого сервиса оформляются в отдельной ветке.
- Общие изменения корня репозитория выносятся в отдельный согласованный коммит.
- Временные файлы, изображения, `node_modules` и локальные артефакты в коммиты не добавляются.

## Слияние

1. Изменения коммитятся в дочерней ветке сервиса.
2. После проверки дочерняя ветка вливается в `service-<microservice>/main`.
3. Слияние в корневую `main` выполняется только после отдельного подтверждения.

Использовать Conventional Commits, например `feat(files): ...`, `fix(tasks): ...` или `chore(tasks): ...`.
